# Первый запуск курса

Цель настройки — открыть учебный notebook и выполнить его сверху вниз в отдельном окружении Python. **Для первого занятия достаточно базового набора; API-ключи и GPU не нужны.** Сохраните весь репозиторий: notebook читает данные из соседней папки `datasets/`.

## 1. Подготовьте Python и папку курса

Рекомендуется **Python 3.12**; общий контрольный прогон выполнен на Python 3.12.14, Linux x86_64, CPU. Установите Python для своей операционной системы с [официального сайта](https://www.python.org/downloads/), выбрав ветку 3.12. Native Windows и macOS не входили в общий compatibility gate; доступность колёс полного DL-набора зависит от платформы.

Скачайте или клонируйте весь репозиторий и распакуйте архив, если он был скачан как ZIP. Откройте терминал **в корне курса**: там должны находиться `README.md`, `course_plan.json`, `requirements-core.txt` и папки `week_01_...` — `week_26_...`. Отдельно скачанный `.ipynb` не содержит все нужные ему датасеты.

## 2. Создайте окружение и установите базовые пакеты

Выполните один набор команд для своей системы.

### macOS / Linux, bash или zsh

```bash
python3.12 --version
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-core.txt jupyterlab
python -m jupyter lab
```

В следующий раз окружение уже существует. Откройте терминал в той же папке и выполните:

```bash
source .venv/bin/activate
python -m jupyter lab
```

### Windows, PowerShell

```powershell
py -3.12 --version
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-core.txt jupyterlab
.\.venv\Scripts\python.exe -m jupyter lab
```

Здесь вызывается Python окружения напрямую, поэтому активационный скрипт PowerShell не требуется. Для следующего запуска достаточно последней команды из корня курса.

Команды `venv` соответствуют [документации Python](https://docs.python.org/3.12/library/venv.html); установка `jupyterlab` через pip — [документации JupyterLab](https://jupyterlab.readthedocs.io/en/stable/getting_started/installation.html). JupyterLab добавляется как интерфейс к учебному kernel. Общий QA проверял исполнение notebook-кода; конкретная версия и интерфейс JupyterLab в этот прогон не входили. При наличии настроенного Jupyter или VS Code можно выбрать в нём Python данного окружения и не устанавливать новый интерфейс.

## 3. Откройте первую практику

После запуска JupyterLab откройте слева папку `week_01_intro_ds_ai`, затем `practice`, затем [01_reproducible_data_analysis.ipynb](week_01_intro_ds_ai/practice/01_reproducible_data_analysis.ipynb).

1. Убедитесь, что kernel использует Python созданного окружения. При нескольких окружениях выберите нужное через меню Kernel.
2. Прочитайте постановку задачи и описание данных в первых Markdown-ячейках.
3. Выберите **Kernel → Restart Kernel and Run All Cells** и подтвердите перезапуск.
4. Дождитесь завершения. Кодовые ячейки должны получить номера исполнения; таблицы и графики появятся под соответствующим кодом.
5. Сохраните notebook. Для своей работы используйте копию файла с понятным именем, сохраняя её в соответствующей папке `practice/` или `homework/`, чтобы относительные пути к данным продолжали работать.

Во время чтения можно выполнять по одной ячейке через **Shift+Enter**. Перед сдачей всегда повторяйте полный запуск с перезапуском kernel: так проверяется, что результат не зависит от старых переменных, созданных в другом порядке.

## 4. Установите ML-расширения к соответствующим неделям

| Набор | Содержание | Где нужен |
|---|---|---|
| [requirements-core.txt](requirements-core.txt) | NumPy, pandas, SciPy, scikit-learn, визуализация и средства исполнения notebook | Базовый курс, классический ML и offline-часть AI-интеграций |
| [requirements-ml.txt](requirements-ml.txt) | Core плюс XGBoost, LightGBM, SHAP, LIME, PyTorch, TensorFlow/Keras | Полный набор для всех 54 notebooks; особенно недели 13, 16, 17 |
| [00_course_admin/requirements-qa-lock.txt](00_course_admin/requirements-qa-lock.txt) | Общие и транзитивные версии проверенной среды | Constraints для воспроизводимости; ориентир для Linux x86_64 / Python 3.12 |

В активном окружении macOS/Linux:

```bash
python -m pip install -r requirements-ml.txt
```

На Windows без активации:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-ml.txt
```

Полный набор включает базовый. Файлы core/ML используют общий lock как ограничения версий, поэтому для начала не требуется устанавливать все DL-библиотеки. Первая установка получает пакеты из сети; после неё учебные notebooks выполняются на CPU и читают локальные данные без внешних загрузок. Полный набор может потребовать заметно больше места, чем базовый.

Референсный полный прогон выполнен на Linux x86_64 с CPU-версией PyTorch и TensorFlow. Если ваша платформа не поддерживает зафиксированное колесо, сохраните полный текст ошибки и используйте согласованную с преподавателем Linux-среду для соответствующего практикума. Молчаливая замена XGBoost/SHAP/PyTorch другим алгоритмом меняет задание. Полный перечень фактически проверенных версий лежит в [validation_all_versions.json](00_course_admin/validation_all_versions.json).

## 5. Работайте с Homework отдельно

Откройте `homework/Homework_Week_XX.md` нужной недели. Рядом лежит стартер: в неделях 01–08 это `Homework_Week_XX.ipynb`, в последующих неделях имя содержит `starter` или `Starter`. Точная ссылка есть в README недели.

Стартер должен запускаться до решения. В нём намеренно остаются TODO, незаполненные результаты и вопросы. **Отсутствие ошибки в Run All не означает, что домашняя выполнена.** Реализуйте требования, постройте результаты и напишите собственную интерпретацию по рубрике. Код основного практикума помогает понять приём; баллы начисляются за самостоятельный результат из задания.

## 6. Переходите к API и облачным сервисам по отдельным лабораторным

Для OpenAI API следуйте [LIVE_API_LAB.md недели 20](week_20_gpt_api_chatbot/practice/LIVE_API_LAB.md): установка live-зависимостей, переменные окружения, выбор доступной модели и явный запуск клиента описаны там. Основной notebook не отправляет запросов к платной модели. Локальная база знаний и retrieval недели 21 также работают без API.

Для [Copilot Studio](week_22_copilot_basics/practice/COPILOT_STUDIO_LAB.md), [интеграций Microsoft 365](week_23_copilot_integrations/practice/COPILOT_INTEGRATIONS_LAB.md), [n8n workflows](week_24_n8n_workflows/practice/N8N_LAB.md) и [n8n AI Agent](week_25_n8n_ai_agents/practice/N8N_AI_AGENT_LAB.md) используйте пошаговые инструкции в соответствующих неделях. В них указаны реальные действия в интерфейсе, импорт JSON, настройка credentials и ожидаемые подтверждения.

Локальная симуляция иллюстрирует алгоритм и проверяет учебный контракт. Реальный запуск в сервисе записывается отдельным результатом с датой и доступной версией. Учебные файлы не содержат секретов; персональные ключи и credentials храните в окружении или предусмотренном сервисом хранилище.

## Если что-то не запускается

| Симптом | Что проверить |
|---|---|
| `python3.12` или `py -3.12` не найден | Установлена ли ветка Python 3.12 и видна ли команда в новом терминале |
| `No module named jupyterlab` | Выполнена ли установка `jupyterlab` тем же Python, которым запускается интерфейс |
| `ModuleNotFoundError` для pandas/sklearn | Установлен ли core и выбран ли kernel именно учебного окружения |
| Не найден xgboost/lightgbm/shap/lime/torch/tensorflow | Установлен ли ML-набор; эти практикумы действительно используют названные библиотеки |
| `No matching distribution found` | Сопоставьте версию Python, архитектуру и ОС с Linux/CPU-референсом; приложите название пакета и полный текст ошибки |
| `FileNotFoundError` для CSV/JSON/SQLite | Сохранён ли полный репозиторий, существует ли `datasets/` недели и остаётся ли notebook внутри её структуры |
| Результат отличается после запуска по одной ячейке | Перезапустите kernel и выполните весь notebook сверху вниз |
| Нет live-ответа Copilot/n8n/API | Проверьте отдельную vendor lab: доступ к сервису, модель, credentials, статус источника и фактический журнал выполнения |

Для проверки выбранного Python можно временно выполнить в notebook:

```python
import sys
print(sys.executable)
print(sys.version)
```

Для обращения к преподавателю приложите номер недели, имя notebook, операционную систему, вывод этих двух строк и полный текст ошибки. API-ключи и другие секреты в отчёт не включаются.
