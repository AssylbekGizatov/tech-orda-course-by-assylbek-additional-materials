## Как проверялся код

[Полный машиночитаемый отчёт](validation_all.json) содержит отдельную запись для каждого notebook: время, статус, число ячеек и графических выводов, SHA-256 исходного содержимого и сохранённого файла. Каждый notebook запускался сверху вниз в **новом настоящем Jupyter kernel**, из своей папки, с остановкой при ошибке. Таким образом, выполнение не опиралось на переменные из предыдущего практикума. Проверка охватила встроенные `assert`, таблицы, обучение моделей и построение графиков.

В неделях 13, 16 и 17 исполнены реальные XGBoost, LightGBM, SHAP, LIME, PyTorch и TensorFlow/Keras. Нейросетевые практикумы обучаются на CPU; seeds зафиксированы, число вычислительных потоков ограничено. В упражнениях с оценкой обобщения используются отдельные train/test-разбиения, а преобразования, подбор параметров и порогов выполняются на обучающих данных. Небольшие учебные результаты предназначены для изучения методов и не устанавливают качество модели для промышленного применения.

При проверке [практикума SHAP/LIME](../week_16_explainability_nn/practice/01_shap_lime_and_neuron.ipynb) исправлен способ задания опорного распределения Tree SHAP: выбран `tree_path_dependent`, использующий число обучающих примеров в путях дерева. Сохранена независимая строгая проверка равенства базового значения плюс суммы вкладов предсказанию модели. После исправления максимальное расхождение составило около `8.53e-14`; практикум повторно прошёл полный запуск. Это также отражено в пояснении и задании недели.

## Среда и установка по этапам

Общий прогон выполнен на **Python 3.12.14, Linux x86_64, CPU**. Точные версии находятся в [манифесте среды](validation_all_versions.json), полный набор зафиксирован в [requirements-qa-lock.txt](requirements-qa-lock.txt). Например, использованы scikit-learn 1.9.1, PyTorch 2.14.1+cpu и TensorFlow CPU 2.21.0. Установка и выбор notebook kernel описаны в [SETUP.md](../SETUP.md).

- [requirements-core.txt](../requirements-core.txt) устанавливает базовые библиотеки анализа, визуализации и Jupyter kernel для начала курса.
- [requirements-ml.txt](../requirements-ml.txt) включает core и добавляет библиотеки недель 13, 16 и 17; этого профиля достаточно для всех 54 offline notebooks. PyTorch берётся из официального индекса CPU-колёс.
- [requirements-live.txt](../requirements-live.txt) отдельно фиксирует опциональный OpenAI SDK. Проверено разрешение его зависимостей; SDK-запросы и аутентификация не исполнялись.

Для core в пустой временной среде разрешилось 57 пакетов, для полного ML-профиля — 103. Constraints сами по себе не устанавливают все пакеты полного набора. Основные инструкции используют pip. При использовании uv для полного ML-профиля требуется выбор версий между PyPI и официальным PyTorch CPU-индексом через `--index-strategy unsafe-best-match`, соответствующий поиску версий pip. Проверенный Linux-прогон не подтверждает доступность всех зафиксированных колёс на каждой другой ОС; версия и интерфейс JupyterLab также не входили в этот прогон.

## Как повторить проверки

Быстрый аудит использует только стандартную библиотеку Python. Он читает файлы, сравнивает структуру, часы, SHA-256, размеры и сохранённые выводы; notebook-код не запускается, файлы не изменяются:

```bash
python scripts/validate_course.py --require-catalog
python scripts/validate_course.py --require-catalog --json
```

Для повторного исполнения после установки полного ML-профиля:

```bash
python scripts/execute_course.py
```

[Этот wrapper](../scripts/execute_course.py) вызывает [проверенный runner](../scripts/validate_weeks_09_17.py) с `--all`: обновляются notebook outputs, контрольные суммы и JSON-отчёты. Генераторы материалов не запускаются. Выборочное исполнение через `--only путь/к/notebook.ipynb` подходит для исправленного файла в той же среде; после смены зависимостей следует выполнить общий прогон. Редактирование или обычное пересохранение notebook может изменить его SHA-256 и потребовать обновления отчёта.

## Границы проверки

Homework-стартеры намеренно содержат незаполненные TODO. Их успешный запуск подтверждает работоспособность заготовок; выполнение задания оценивается отдельно по недельной рубрике.

Основные notebooks работают с локальными данными и offline-примерами. Платные API-запросы не отправлялись. Работа аккаунтов, credentials, публикации и фактические ответы OpenAI API, Copilot Studio, Microsoft 365 и n8n требуют самостоятельного прохождения соответствующих vendor labs; локальная симуляция не является подтверждением работы облачного сервиса.

В [RESOURCE_CATALOG.json](../RESOURCE_CATALOG.json) учтены 78 недельных копий материалов: 55 PDF, 15 HTML и 8 Markdown-документов; уникальных файлов — 69. Итоговый [аудит](../scripts/validate_course.py) подтвердил все 78 размеров и SHA-256, отсутствие пропущенных файлов и совпадение всех 54 notebook-файлов с отчётом исполнения. Контрольная сумма подтверждает целостность скачанного файла. Педагогическая роль, выбранные страницы, уровень и время чтения описаны отдельно в недельных `presentations/README.md` и [каталоге материалов](../RESOURCE_CATALOG.md).
